# 05 — Danh sách API

- Base: `/v1`, trừ health (`VERSION_NEUTRAL`).
- Mọi route mặc định yêu cầu `Authorization: Bearer <access>`. Route `@Public()` được đánh dấu **Public**.
- Ký hiệu quyền: xem [04-authorization.md](04-authorization.md). "Member+" = Member trở lên.
- Response thành công: `{ data, meta: { statusCode, requestId } }`; danh sách: `data` là mảng, `meta.nextCursor`, query `?cursor=&limit=`. Lỗi: `{ error: { code, statusCode, message, details?, requestId } }`. `204` không có body; `/health/*` trả body thô. Xem [07-conventions.md](07-conventions.md) §2–3.

## Rate limit (M11 B3)

Mọi route HTTP (trừ `/health/*`) qua `AppThrottlerGuard` sau `JwtAuthGuard`; đếm trong Redis (sliding log, dùng chung giữa các instance). Đã đăng nhập → khoá theo người dùng; chưa → theo IP (`req.ip`, chỉ lấy từ `X-Forwarded-For` khi `TRUST_PROXY_HOPS` > 0). Vượt → **429 `RATE_LIMITED`** + `Retry-After` (giây), bị chặn trong suốt một `ttl`. Header thành công: `X-RateLimit-Limit` / `-Remaining` / `-Reset` (throttler `credential` / `account` thêm hậu tố `-credential` / `-account`).

| Route                                                    | Giới hạn                                                             |
| -------------------------------------------------------- | -------------------------------------------------------------------- |
| Mặc định                                                 | 300 / phút                                                           |
| `POST /auth/login`                                       | 30 / phút / IP **và** 5 / phút / (IP, email) **và** 20 / giờ / email |
| `POST /auth/register`                                    | 10 / giờ / IP                                                        |
| `POST /auth/refresh`                                     | 30 / phút / IP                                                       |
| `POST /invites/:token/accept`                            | 20 / phút / người                                                    |
| `POST /orgs/:orgId/invites`, `POST /orgs/:orgId/uploads` | 60 / giờ / người                                                     |
| `GET /orgs/:orgId/search/transcripts`                    | 60 / phút / người                                                    |
| `GET …/meetings/:meetingId/transcript/export`            | 30 / phút / người                                                    |
| `PATCH …/meetings/:meetingId/transcript/segments/:seq`   | 120 / phút / người                                                   |

Redis lỗi → cho qua (fail-open, có log).

## Channels (tag `Channels`)

## Action items (tag `Action items`, M12)

Prefix `/v1/orgs/:orgId`. Quyền ĐỌC = quyền XEM meeting (04 §3); không có quyền riêng. Mỗi việc: `{ id, meetingId, meetingTitle, origin (ai|manual), task, ownerName, assignee { id, displayName } | null, dueText, dueDate, status (open|done|dismissed), completedAt, version, createdAt }`. `ownerName` là chữ model nghe được (kể cả khi chưa map được thành viên); `assignee` null = chưa giao / không map được / người đó đã rời tổ chức. API ghi (tạo, sửa, đổi trạng thái) ở B5.

## Realtime (Socket.IO, namespace `/realtime`)

- Kết nối: `io('/realtime', { auth: { token: '<access JWT>' } })` (token trong `auth`, KHÔNG trong query string — query string nằm trong log của proxy). Middleware của namespace xác thực trong handshake, cùng hai lớp với REST: chữ ký + hạn JWT, rồi phiên còn sống. Bị từ chối → client nhận `connect_error` với `err.data = { code, statusCode, message }`, cùng mã với REST: `AUTH_TOKEN_MISSING`, `AUTH_TOKEN_INVALID`, `AUTH_TOKEN_EXPIRED`, `AUTH_SESSION_REVOKED` (M7 B1).
- Server tự join `user:{userId}` và `session:{sessionId}` (để ngắt đúng phiên khi logout — M7 Q1). Client gửi `subscribe { meetingId }`, server kiểm tra quyền xem rồi mới join `meeting:{meetingId}`.
- `subscribe { meetingId }` / `unsubscribe { meetingId }` trả qua **ack** (M7 B3, Q4): `{ data: { meetingId } }` hoặc `{ error: { code, statusCode, message } }`. Quyền = điều kiện xem dùng chung của REST (04 §3): server tự tìm org của meeting rồi vai trò của người gọi trong org đó. Không xem được / không tồn tại → `NOT_FOUND`; payload sai → `VALIDATION_FAILED`. `unsubscribe` khi chưa subscribe → vẫn ok.
- **Nhiều instance (M7 B4):** Redis adapter (kênh `REALTIME_REDIS_KEY`, mặc định `meetnote:socket.io`) — event, `disconnectSockets`, `fetchSockets` vào một room chạy đúng dù socket ở instance khác; worker phát qua `@socket.io/redis-emitter` (cùng kênh). **Origin:** chỉ origin trong `REALTIME_CORS_ORIGINS` mở được socket từ trình duyệt (kiểm ở `allowRequest`, vì CORS không áp cho WebSocket).
- **Mất quyền là rời room (M7 B5, Q2):** sau commit, mọi thao tác làm mất quyền xem phát "kiểm lại" (`serverSideEmit` qua Redis) theo phạm vi: **meeting** (gỡ share, xoá meeting), **người** (bị gỡ khỏi / rời kênh hoặc tổ chức, Admin org bị hạ xuống member), **kênh** (công khai → riêng tư, xoá kênh), **tổ chức** (xoá tổ chức). Mỗi api instance kiểm lại socket CỦA MÌNH trong đúng phạm vi đó bằng điều kiện xem dùng chung; socket không còn xem được → rời room + `meeting.access_revoked`. `subscribe` kiểm quyền lần hai SAU khi vào room để không lọt khe giữa lần kiểm đầu và `join`.
- **Trang thử** `/realtime-test.html` (chỉ `NODE_ENV=development`): dán access token, kết nối, subscribe meeting, xem event. Client Socket.IO lấy từ chính server (`/socket.io/socket.io.js`).

| Event (server → client)  | Room                                 | Payload                                                                                                                                                                                                                                     |
| ------------------------ | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `session.ended`          | socket bị ngắt (riêng từng socket)   | `{ reason: "token_expired" \| "session_revoked" }` — gửi NGAY TRƯỚC khi server ngắt (M7 B2)                                                                                                                                                 |
| `meeting.access_revoked` | socket vừa bị cho rời `meeting:{id}` | `{ meetingId }` — mất quyền xem (M7 B5)                                                                                                                                                                                                     |
| `meeting.progress`       | `meeting:{id}`                       | `{ meetingId, stage: "transcribe", percent }` — từ worker khi whisper báo tiến độ, giãn tối thiểu 5 % / lần (M6 B6)                                                                                                                         |
| `meeting.status`         | `meeting:{id}`, `user:{ownerId}`     | `{ meetingId, status, failureCode }` — phát SAU commit: complete upload tạo meeting `queued` (M7); pipeline đổi chặng `preprocessing` → `transcribing` → `summarizing` → `completed` / `failed` (M6 B6, cùng helper `publishMeetingStatus`) |
| `notification.created`   | `user:{id}`                          | `NotificationResponseDto` — sau commit (M10)                                                                                                                                                                                                |
| `notification.read`      | `user:{id}`                          | `{ ids: [id] }` (đọc một) hoặc `{ all: true, orgId }` (đọc hết; chỉ phát khi có dòng đổi) — để các phiên khác cập nhật số chưa đọc; `{ all }` là gợi ý, client lấy lại `unread-count` (M10 B4)                                              |
| `report.ready`           | thông qua `notification.created`     | (không có event riêng — client nhận thông báo, payload ở bảng loại thông báo)                                                                                                                                                               |

> **Bẫy:** Access token hết hạn khi socket vẫn đang mở. Server lưu `exp` lúc handshake và chủ động ngắt khi hết hạn (`session.ended { reason: token_expired }`), client refresh qua REST rồi kết nối lại bằng token mới. Phiên bị thu hồi (logout, logout-all, xoá phiên ở `/me/sessions`, phát hiện reuse refresh token) → ngắt NGAY mọi socket của phiên đó (room `session:{sid}`; logout-all: `user:{id}`) qua Redis, đúng cả khi socket ở instance khác (M7 B2).
